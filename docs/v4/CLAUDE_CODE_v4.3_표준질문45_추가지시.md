# AuditRAG v4.3 추가 지시서: 표준 질문 45개로 평가 (Claude Code용)

- **기준:** v4.1 구현 지시서와 v4.2 추가 지시서. 이 문서와 충돌하면 이 문서를 따른다.
- **결정 사항(사용자):**
  - 논문 평가는 감사인 표준 질문 45개(논문 부록 A)만으로 한다.
  - 사건별 맞춤 질의는 만들지 않는다. 케이스에 따른 추가 질문은 실무 활용 영역으로 두고 평가에 넣지 않는다.

---

## 1. 질의 파일

`experiments_v4/data/queries.jsonl`에 함께 전달한 `queries_45.jsonl`을 그대로 넣는다.

```json
{"qid": "q1.1", "text": "들러리 입찰이나 담합의 정황이 있는 입찰건을 찾아줘", "area": "1",
 "support_class": "A", "support_group": "search", "type": "semantic", "split": "test",
 "query_lang": "ko", "target_evidence_lang": "", "source_question": "1.1", "note": ""}
```

| 필드 | 값 | 비고 |
|---|---|---|
| `qid` | `q` + 질문 번호(`q1.1`~`q7.2`) | 45개 |
| `text` | 부록 A 질문 문장 | 띄어쓰기와 오탈자만 바로잡았다. 바꿔 쓰거나 지시문, 필터를 덧붙이지 않는다 |
| `area` | 영역 1~7 | 부록 A 영역 |
| `support_class` | A, A′, C, D, B, E | 부록 A 분류 |
| `support_group` | `search`(A, A′ 17개), `meta`(C 3개), `nonsearch`(D, B, E 25개) | 분석 집합 구분 |
| `type` | `exact` 2, `semantic` 9, `relation` 6. 나머지는 `none` | `search` 집합에만 유형이 있다 |
| `split` | 모두 `test` | 개발용(dev) 질의는 없다 |

- **P0 예외:** 이 파일은 사건 정보가 없는 일반 질문이고 논문 부록에 실리는 내용이라, Claude Code가 읽어도 된다. 다른 P0 경로(정답, 판정 시트, 색인, 원본, 실패 분석 시트)는 그대로 금지한다.
- **입력 검증**(v4.2 Q2의 60~80개, dev 20개 검증을 대체):
  - 45줄이고 `qid`가 중복되지 않는다
  - `support_class`가 정해진 6개 값 안에 있다
  - `search` 집합은 `type`이 `exact`, `semantic`, `relation` 가운데 하나이다
  - 나머지 집합은 `type`이 `none`이다

## 2. 동작 점검(dev 대체)

- 개발용 질의 20개는 없앤다.
- 실데이터 동작 확인은 표준 질문 3개(`q1.1`, `q2.6`, `q7.2`)로 하되, 보고는 오류 여부, 응답 시간, GPU 메모리만 한다. 순위와 점수는 보고하지 않는다.
- 이 결과를 보고 설정을 바꾸지 않는다. 설정은 v4.1 기본값으로 고정한다.

## 3. 분석 집합(실험 전에 고정)

| 집합 | 질의 | 용도 |
|---|---|---|
| **S17**(주 분석) | `support_group = search` 17개 | 사전 지정 비교 11개(v4.1 §6.4)의 검정과 Holm 보정은 이 집합의 nDCG@10으로 한다. T2~T6, F1의 기본 집합 |
| ALL45 | 45개 전체 | 기술 통계만 낸다(평균과 95% 신뢰구간). 검정하지 않는다 |
| 집합별 비교 | `search` 17, `meta` 3, `nonsearch` 25 | 표준 질문 분류가 실제 검색 결과와 맞는지 확인하는 표(새 표 T8) |

- `config.yaml`에 `primary_subset: search`를 적고, 실행 전에 바꾸지 않는다.
- 이 값은 E1 환경 기록에도 남긴다.

## 4. 지표 추가

- **P@10 추가:** 상위 10개 가운데 등급 1 이상 단위 비율(ranx `precision@10`)이다. 표준 질문은 범위가 넓어 관련 단위가 10개를 넘는 질의가 있을 수 있으므로, Recall@10과 함께 낸다.
  - T2: nDCG@10, P@10, Recall@10, Recall@10(등급 2, n), MRR@10, Recall@100 순서
  - T8에도 포함
- **새 표 T0b, 질의별 관련 단위 분포:** 판정 후 집합별(S17, meta, nonsearch)로 아래를 낸다. Recall@10을 해석하는 데 필요하다.
  - 등급 1 이상 단위 수의 평균, 중앙값, 최대
  - 등급 2 단위 수의 평균, 중앙값, 최대
  - 관련 단위가 0개인 질의 수
  - 관련 단위가 10개를 넘는 질의 수

## 5. 판정

- **판정 시트:** 45개 질의 전체를 v4.1 방식대로 만든다(9개 실행 상위 10개 합집합, 출처 가림, 순서 섞음). 예상 판정량은 약 1,100~2,000개 단위이다.
- **판정자 B:** 11개 질의를 판정한다.
  - `support_group`별로 층화해 고른다: search 4, meta 1, nonsearch 6
  - seed는 고정한다
  - 고른 질의 목록(`qid`만)을 보고한다
- **판정 기준 문서 보강:** v4.2 J2 문서에 아래 안내를 [사용자 확정] 표시와 함께 넣는다. 집계나 비교를 요구하는 질문도 같은 기준으로 판정하기 위해서이다.
  > 질문이 여러 자료를 모아야 답할 수 있는 형태이더라도, 그 답을 단독으로 보여 주는 단위(예: 입찰 참여 업체가 정리된 표, 견적 조건 변경을 지시한 메일)는 2, 답을 찾는 단서가 되는 단위는 1, 관련 없는 단위는 0으로 매긴다.

## 6. 표 구성 변경

| 표 | 변경 |
|---|---|
| T0([표 8]) | 행: 영역 1~7과 계. 열: A, A′, C, D, B, E 수와 `search` 집합의 유형별 수. 부록 A 표와 같은 값이 나와야 한다(검증용) |
| T2([표 12]) | S17 기준, P@10 열 추가. ALL45 표를 부가로 낸다 |
| T3([표 15]) | S17 기준. 유형별 차이 열의 n은 exact 2, semantic 9, relation 6이므로 exact는 `†사례 수준` 표시(v4.2 E8) |
| T4([표 16]) | S17 기준. 같은 표시 규칙 |
| T5([표 17]) | S17 기준. 증거 언어는 판정 후 등급 2 단위로 정한다(목표 언어 지정 없음). 그룹 n < 5면 `†사례 수준` |
| T6([표 18]) | S17 기준. ALL45는 부가 |
| T7 | 응답 시간은 45개 전체로 잰다 |
| **T8(신설)** | 행: search 17, meta 3, nonsearch 25, 전체 45. 열: n, R2, R4, R6, R8의 nDCG@10과 P@10 |
| F1 | S17의 놓친 등급 2 단위만 대상으로 한다 |
